Step-by-step workflow
1

Select your SQL dialect BASIC

At the top of the left panel, choose the database engine you are targeting — PostgreSQL, MySQL, SQLite, SQL Server, Microsoft SQL Server, or Oracle. The generated query will use the exact syntax, functions, and date formats for that engine. You can switch dialects any time before generating.

2

Paste your schema (optional but recommended) BASIC

Toggle on Schema Context and paste your CREATE TABLE statements. This lets the AI use your exact table and column names instead of guessing them. Without a schema, the AI will still work but may invent plausible-sounding names.

CREATE TABLE orders ( id INT PRIMARY KEY, user_id INT, total DECIMAL(10,2), status VARCHAR(20), created_at TIMESTAMP );
3

Type what you want in plain English BASIC

In the conversation box at the bottom, describe the data you need naturally. You do not need to know any SQL. For example: "Show me all orders placed last month where the total is over 500, sorted by newest first."

4

Press RUN or hit Enter BASIC

Click the RUN → button or press Enter (use Shift+Enter for a new line). The generated SQL appears in the right panel with syntax highlighting, an explanation, and a clause-by-clause breakdown.

5

Refine with follow-up messages PRO

The conversation remembers context. After generating, you can say things like "also group it by region" or "add a filter for active users only" — the AI will build on the previous query. No need to repeat yourself.

6

Copy or download the result BASIC

In the SQL Output panel, use the COPY button to copy to clipboard or DOWNLOAD to save as a .sql file. Your query history is saved in the History tab for the session.

💡

First time? Use the Quick Example chips in the left panel — click any chip to pre-fill the input and see how the tool works without having to think of a query.

Supported database engines
PG

PostgreSQL

Full support for CTEs (WITH), window functions (OVER PARTITION BY), ILIKE, RETURNING, array types, and JSONB operators. Best choice for modern relational workloads.

MY

MySQL

Uses LIMIT/OFFSET, backtick identifiers, NOW(), and MySQL-specific string functions like GROUP_CONCAT. Generates compatible syntax for MySQL 8+.

SL

SQLite

Lightweight syntax, no stored procedures. Uses strftime() for date formatting. Good for embedded apps, mobile, and local development.

SS

SQL Server

Generates T-SQL with TOP N instead of LIMIT, uses GETDATE(), bracket identifiers [column], and supports OFFSET FETCH for pagination.

MS

Microsoft SQL Server (MSSQL) PRO

Full T-SQL dialect — SELECT TOP, NOLOCK hints, TRY_CAST, STRING_AGG, DATEFROMPARTS, and SSMS-compatible formatting. Use this for Azure SQL and on-premise MSSQL environments.

OR

Oracle

Uses ROWNUM / FETCH FIRST N ROWS ONLY, SYSDATE, dual table selects, and Oracle-specific functions like NVL and DECODE.

⚡

Switching dialects mid-session: You can change the dialect at any time. The next query you generate will use the new dialect. However, the conversation history still refers to old queries — so for a fully clean slate in a new dialect, refresh the page.

How to use schema context
①

Toggle Schema Context on BASIC

Click the Schema Context toggle switch in the Configuration panel. A text area will expand below it.

②

Paste your CREATE TABLE statements BASIC

Copy your table definitions from your database client (pgAdmin, DBeaver, MySQL Workbench, SSMS, etc.) and paste them in. You can paste multiple tables — the AI reads all of them.

CREATE TABLE users ( id SERIAL PRIMARY KEY, name VARCHAR(100) NOT NULL, email VARCHAR(200) UNIQUE, role VARCHAR(20) DEFAULT 'user', created_at TIMESTAMP DEFAULT NOW() ); CREATE TABLE orders ( id SERIAL PRIMARY KEY, user_id INT REFERENCES users(id), total DECIMAL(10,2), status VARCHAR(20), placed_at TIMESTAMP );
③

What happens with your schema BASIC

The AI will use your exact table names, column names, types, and relationships. It will also correctly infer join conditions (e.g. orders.user_id = users.id) without you needing to specify them.

④

No schema mode TIP

If you leave Schema Context off, the AI works in best-effort mode. It will generate SQL using common, sensible table and column names based on your description. These may need light editing to match your real schema. Warnings will be shown in yellow when assumptions are made.

🔒

Privacy note: Your schema is sent to the AI API only at query generation time. Nothing is stored server-side between sessions. Refresh the page to clear all data.

How to write effective natural language queries
→

Be specific about what you want to see BASIC

Instead of "get users", try "get the name and email of all users who signed up in the last 30 days." The more detail you give, the more precise the query.

→

Mention sorting, grouping, and limits BASIC

Say things like "sorted by total revenue descending", "grouped by country", or "show only the top 5 results." These map directly to ORDER BY, GROUP BY, and LIMIT/TOP clauses.

→

Describe joins in plain terms BASIC

You can say "show orders with the customer name" or "join users and orders". The AI figures out the join condition, especially if you've provided a schema. For LEFT JOINs, say "include users even if they have no orders."

→

Use aggregations naturally BASIC

Phrases like "total sales per customer", "average order value by month", or "count of active users" all map to SUM, AVG, and COUNT with GROUP BY.

→

Ask for CTEs or subqueries PRO

You can request "write this using a CTE" or "use a subquery to find customers who have spent more than average." The AI will structure the query accordingly.

→

Window functions PRO

Try "rank customers by total spend within each region" or "show running total of revenue by date." This triggers RANK(), ROW_NUMBER(), or SUM() OVER() window functions.

→

Refinement follow-ups PRO

After a query is generated, send a follow-up like "also filter where status is active", "remove the LIMIT", or "add the product name column." The AI builds on the previous query without you repeating everything.

Understanding the output panel
🖊

SQL Output tab

Displays the generated query with full syntax highlighting — keywords in blue, strings in green, numbers in amber, functions in purple.

⊞

Breakdown tab

Each SQL clause (SELECT, FROM, WHERE, JOIN, GROUP BY, etc.) is listed separately with a plain-English description of what it does.

◷

History tab

Every query you generate this session is saved here. Click any history item to reload that query. Useful for comparing results.

📋

Copy to clipboard

The COPY button in the SQL Output header copies the raw, unformatted SQL to your clipboard — ready to paste into your database client.

⬇

Download as .sql

The DOWNLOAD button saves the query as a .sql file to your computer. Useful for sharing or version controlling your queries.

⚠

Warnings

Yellow warning boxes appear when the AI made assumptions — e.g. if "recent" was interpreted as "last 30 days." Review them to fine-tune your query.

Explanation block

Below every generated SQL block, a plain-English explanation tells you exactly what the query does — what data it returns, how the filtering works, and any joins involved. This is useful for sharing queries with non-technical teammates.

Advanced techniques
★

Multi-table schemas give the best results PRO

Paste all related tables at once. The AI maps foreign keys automatically. For example, pasting users, orders, and products lets it write accurate three-table join queries.

★

Request specific output formats PRO

Ask for "write this as a view", "make this a stored procedure", or "wrap it in a transaction." The AI will produce the correct DDL or DML wrapper for your target dialect.

★

Ask for performance hints PRO

After generating, say "what indexes would help this query?" or "is there a more efficient way to write this?" The AI will suggest optimizations in the conversation.

★

Quick Example chips TIP

Click any chip in the Quick Examples section to pre-fill the input with a real-world query pattern. This is the fastest way to explore the tool's capabilities — modify the pre-filled text to fit your schema.

★

Destructive queries — INSERT, UPDATE, DELETE TIP

The AI will generate INSERT, UPDATE, and DELETE queries when asked. For destructive operations, it always adds a warning so you can review before running. Always test on non-production data first.

🚀

Power user flow: Paste schema → generate a base SELECT → use follow-ups to add filters, joins, and aggregations → switch to Breakdown tab to review each clause → copy and run. This iterative approach produces production-ready queries in under 2 minutes.
